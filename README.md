# SchoolConnect Attendance

> 여러 사람이 기록하던 출결 정보를 하나의 역할 기반 흐름으로 바꾼 학교 출결 관리 웹앱

[라이브 데모](https://school-connect-attendance-2013abfd.base44.app/) · [GitHub 프로필](https://github.com/vosnuev)

## 한눈에 보기

| 항목 | 내용 |
| --- | --- |
| 문제 | 담임과 교과교사 10여 명의 출결 기록이 계속 어긋나 월 마감 누락이 발생 |
| 사용자 | 학부모·학생, 담임, 교과교사 |
| 해결 | 학부모 입력 → 담임 확인·수정 → 교과교사 조회·마감으로 역할과 데이터 흐름 분리 |

| 기술 | React, Tailwind CSS, Vite, Base44 인증·DB·호스팅, PWA/SPA |

## 문제

고교학점제 도입 후 담임 혼자 관리하던 출결을 여러 교과교사가 함께 입력·수정·마감하게 됐습니다. 43명 학급에서 하루 약 10건의 출결 변경이 생겼고, 10여 명의 교사가 가진 기록이 서로 달랐습니다.

처음에는 Google Form과 공유 스프레드시트로 해결했습니다. 하지만 데이터가 누적될수록 조회와 수정이 어려워졌고, 같은 정보를 여러 사람이 다시 확인하는 구조 자체가 문제라는 것을 확인했습니다.

## 핵심 판단

안내 문구를 늘리는 대신, 먼저 역할과 책임을 나눴습니다.

```text
학부모·학생 입력
        ↓
담임 확인·수정
        ↓
교과교사 조회·마감
```

- 입력 지점을 한곳으로 모아 단일 원천을 만들었습니다.
- 출결을 `유형(인정·질병·미인정) → 분류(결석·지각·조퇴·결과)`의 2단계로 제한해 유효한 조합만 입력하게 했습니다.
- 다수 학생을 선택해도 학생별 개별 레코드로 저장해 집계와 수정이 가능하도록 했습니다.
- 제출자 역할을 데이터에 남겨 학생·학부모 입력을 구분할 수 있게 했습니다.

## 검증된 결과

- 월말 마감 자료 대조 기준 누락률 **80% → 5%**
- 전체 입력 중 학부모 직접 입력 **60%**
- 다른 학급으로 사용 확산
- 교직 업무 성과급 **S등급**의 근거 중 하나

위 수치는 실제 운영 과정에서 본인이 측정하거나 학교 기록으로 확인한 값입니다.

## 구현 범위

- 출결 입력 및 반복 날짜 선택
- 학생 다중 선택과 학생별 레코드 생성
- 역할별 입력·확인·조회 흐름
- 대시보드 통계, 주간 차트, 최근 기록
- 출결 목록 조회·수정
- 회원가입 사용자 접근과 OAuth 동의 화면

## 기술 선택

Base44를 사용한 이유는 반복 UI 구현보다 현장 요구사항과 데이터 흐름 정의에 집중하기 위해서였습니다. 자연어 요구 → 구현 → 미리보기 → 수정 요청의 짧은 반복으로 인증·DB·호스팅이 포함된 웹앱을 만들었습니다.

이 저장소는 Base44에서 운영 중인 앱의 **포트폴리오용 케이스 스터디**입니다. 현재 플랜에서는 GitHub 소스 내보내기가 지원되지 않아, 원본 소스가 포함된 저장소처럼 오해시키지 않습니다.

## 알려진 한계와 다음 개선

- 학부모 확인서의 스키마를 학생 신고와 동일한 2단계 구조로 맞춰야 합니다.
- 대시보드 엑셀 다운로드가 이전 필드명을 참조하는 문제를 수정해야 합니다.
- 기록이 커질 때를 대비해 서버 집계와 기간 필터가 필요합니다.
- 사용자별 세부 행 단위 권한(RLS)은 아직 구현하지 않았습니다.
- 카카오 1:1 자동 연락은 API 구조 제약으로 중단하고 엑셀 메시지 생성 방식으로 대체했습니다.

## 공개 범위

- 학생 실명, 연락처, 실제 출결 기록은 공개하지 않습니다.
- 인증정보와 운영 데이터는 저장소에 포함하지 않습니다.
- 개인 프로젝트이며, 성과 수치는 적용 범위와 검증 방법을 함께 표기합니다.
